# تشغيل المنصة على Supabase

تبقى الواجهة على GitHub Pages، وتصبح قاعدة البيانات وتسجيل الدخول على Supabase. بعد إكمال الخطوات تختفي رسالة «نسخة عرض للقراءة فقط»، ويعمل تسجيل الدخول والتعديل والاعتماد وسجل التعديلات.

## ما الذي يُحفظ في الواجهة؟
- **في الواجهة (`public/config.js`):**
  - **رابط المشروع:** `https://znisbyqyygdholobhohu.supabase.co`
  - **المفتاح العام (Publishable key):** هذا المفتاح مخصص للواجهات ونشره آمن.
- **ما يحمي البيانات فعليًا:**
  - **سياسات RLS والدوال المحمية في قاعدة البيانات:**
    - الزائر يرى الأسئلة دون إجابات.
    - المعلم المفعَّل يرى الإجابات.
    - التعديل والاعتماد للمراجع والمشرف فقط.
    - كل تعديل يُسجل باسم صاحبه.
  - **لا كتابة مباشرة على الجداول:** كل كتابة تمر عبر دوال تتحقق من الدور.
- **لا تضعه أبدًا في الواجهة ولا ترسله في المحادثة:**
  - مفتاح `service_role` أو `secret`.
  - كلمة مرور قاعدة البيانات.

## الخطوة 1: إنشاء الجداول (مرة واحدة)
1. افتح المشروع في Supabase، ثم **SQL Editor**، ثم **New query**.
2. افتح الملف [`supabase/schema.sql`](../supabase/schema.sql) على GitHub، واضغط **Raw**، وانسخ المحتوى كله.
3. الصقه في المحرر، ثم اضغط **Run**. يجب أن تظهر الرسالة `Success. No rows returned`.

## الخطوة 2: تحميل البيانات (7 أجزاء)
كرر لكل ملف بالترتيب، من `01.sql` إلى `07.sql`، في مجلد [`supabase/seed/`](../supabase/seed/):
- **New query**، ثم الصق محتوى الملف (من زر Raw)، ثم **Run**.
- كل جزء أقل من 1 ميغابايت، وآمن لإعادة التنفيذ؛ لن تتكرر البيانات لو شغّلته مرتين.

بعد آخر جزء شغّل [`supabase/seed/verify.sql`](../supabase/seed/verify.sql). يجب أن تكون كل الأعمدة `true`:
- 7 فصول.
- 28 درسًا.
- 258 هدفًا.
- 111 محتوى مكمّلًا.
- 2580 سؤالًا مع إجاباتها.

قرار الاعتماد الموثق في `data/approvals.json` يُحمَّل كما هو: كل الأسئلة «معتمدة» بقرار مالك المشروع، ومسجلة في سجل التعديلات.

## الخطوة 3: إغلاق التسجيل الذاتي (مستحسن)
افتح **Authentication**، ثم **Sign In / Providers**، وأوقف **Allow new users to sign up**.
- **الأثر:** لا يستطيع أحد إنشاء حساب بنفسه.
- **لو بقي التسجيل مفتوحًا:** أي حساب جديد يكون «بانتظار التفعيل» ولا يرى الإجابات حتى تحدد دوره.

## الخطوة 4: إنشاء الحسابات
1. افتح **Authentication**، ثم **Users**، ثم **Add user**، ثم **Create new user**.
2. أدخل البريد وكلمة مرور قوية، وفعّل **Auto Confirm User**.
3. أنشئ حسابك (المشرف)، وحساب المراجع عبدالله حمدي، وحسابات المعلمين عند الحاجة.
4. حدد الأدوار من **SQL Editor**، مع استبدال البريد ببريد كل حساب:

```sql
update public.profiles set role = 'admin',    display_name = 'مالك المشروع' where email = 'owner@example.com';
update public.profiles set role = 'reviewer', display_name = 'عبدالله حمدي' where email = 'reviewer@example.com';
-- معلم يرى الإجابات دون صلاحية تعديل:
update public.profiles set role = 'viewer',   display_name = 'اسم المعلم'  where email = 'teacher@example.com';
-- عرض كل الحسابات وأدوارها:
select email, display_name, role from public.profiles order by created_at;
```

**الأدوار:**

| الدور | الصلاحية |
| --- | --- |
| `admin` | كل الصلاحيات |
| `reviewer` | التعديل والاعتماد والاستبعاد وسجل التعديلات وتصدير CSV |
| `viewer` | يرى الإجابات فقط |
| `pending` | لا يرى الإجابات |

## الخطوة 5: الاستخدام
- افتح رابط الموقع على GitHub Pages، ثم «تسجيل الدخول» بالبريد وكلمة المرور.
- منشئ الاختبارات يعمل كما هو، ويقرأ البنك من قاعدة البيانات مباشرة.
- تصدير CSV يتم في المتصفح من صفحة بنك الأسئلة، للمراجع والمشرف فقط.

## التحديث لاحقًا
- **تعديل ملفات `data/`:**
  1. شغّل `npm run build-supabase-seed`.
  2. نفّذ الأجزاء الجديدة. الإضافات فقط تُدرج، والسجلات الموجودة لا تُستبدل، فلا تضيع تعديلات المراجعين في قاعدة البيانات.
- **تعديل `schema.sql`:** أعد تنفيذه كاملًا. هو آمن للتكرار، ولا يحذف بيانات.

## الاختبار
- `test/supabase-e2e.mjs` يشغّل الواجهة في المتصفح على قاعدة PostgreSQL محلية مطابقة للمخطط. يستخدم محاكيًا لمكتبة supabase-js ينفذ كل طلب بدور `anon` أو `authenticated`، فتُختبر سياسات RLS والدوال فعليًا.
- النتيجة: 24 فحصًا ناجحًا:
  - الزائر لا يرى الإجابات.
  - الحساب غير المفعّل لا يرى الإجابات.
  - المعلم يرى الإجابات دون أدوات المراجعة.
  - المراجع يعدّل فيتحول السؤال إلى «قيد المراجعة»، ثم يعيد اعتماده.
  - سجل التعديلات يعرض الاسم.
  - تصدير CSV.
  - منشئ الاختبارات.
- **حدود الاختبار:**
  - لم يُختبر بعد على مشروع Supabase الحقيقي، لأن بيئة التطوير لا تصل إلى `*.supabase.co`.
  - Supabase Auth نفسه (التحقق من كلمة المرور) لم يُختبر محليًا، لأن المحاكي يتجاوزه.
