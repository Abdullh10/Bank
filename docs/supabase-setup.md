# تشغيل المنصة على Supabase

تبقى الواجهة على GitHub Pages، وتصبح قاعدة البيانات وتسجيل الدخول على Supabase. بعد إكمال الخطوات تختفي رسالة «نسخة عرض للقراءة فقط»، ويعمل تسجيل الدخول والتعديل والاعتماد وسجل التعديلات.

## ما الذي يُحفظ في الواجهة؟
- **في الواجهة (`public/config.js`):**
  - **رابط المشروع:** `https://znisbyqyygdholobhohu.supabase.co`
  - **المفتاح العام (Publishable key):** هذا المفتاح مخصص للواجهات ونشره آمن.
- **ما يحمي البيانات فعليًا:**
  - **سياسات RLS والدوال المحمية في قاعدة البيانات:**
    - الزائر لا يرى شيئًا: أول صفحة هي صفحة الدخول، وقاعدة البيانات ترفض أي قراءة من غير المسجلين.
    - الحساب غير المفعَّل (`pending`) يرى رسالة «بانتظار التفعيل» فقط.
    - المعلم المفعَّل يرى المحتوى مع الإجابات.
    - التعديل والاعتماد للمراجع والمشرف فقط.
    - كل تعديل يُسجل باسم صاحبه.
  - **لا كتابة مباشرة على الجداول:** كل كتابة تمر عبر دوال تتحقق من الدور.
- **لا تضعه أبدًا في الواجهة ولا ترسله في المحادثة:**
  - مفتاح `service_role` أو `secret`.
  - كلمة مرور قاعدة البيانات.

## الخطوة 1: إنشاء الجداول (مرة واحدة)
1. افتح المشروع في Supabase، ثم **SQL Editor**، ثم **New query**.
2. افتح الملف [`supabase/schema.sql`](../supabase/schema.sql) على GitHub، واضغط **Raw**، وانسخ المحتوى كله.
3. الصقه في المحرر، ثم اضغط **Run**. يجب أن تظهر الرسالة `Success. No rows returned`.

## الخطوة 2: تحميل البيانات (7 أجزاء)
كرر لكل ملف بالترتيب، من `01.sql` إلى `07.sql`، في مجلد [`supabase/seed/`](../supabase/seed/):
- **New query**، ثم الصق محتوى الملف (من زر Raw)، ثم **Run**.
- كل جزء أقل من 1 ميغابايت، وآمن لإعادة التنفيذ؛ لن تتكرر البيانات لو شغّلته مرتين.

بعد آخر جزء شغّل [`supabase/seed/verify.sql`](../supabase/seed/verify.sql). يجب أن تكون كل الأعمدة `true`:
- 7 فصول.
- 28 درسًا.
- 258 هدفًا.
- 111 محتوى مكمّلًا.
- 2580 سؤالًا مع إجاباتها.

قرار الاعتماد الموثق في `data/approvals.json` يُحمَّل كما هو: كل الأسئلة «معتمدة» بقرار مالك المشروع، ومسجلة في سجل التعديلات.

## الخطوة 3: إغلاق التسجيل الذاتي (مستحسن)
افتح **Authentication**، ثم **Sign In / Providers**، وأوقف **Allow new users to sign up**.
- **الأثر:** لا يستطيع أحد إنشاء حساب بنفسه.
- **لو بقي التسجيل مفتوحًا:** أي حساب جديد يكون «بانتظار التفعيل» ولا يرى الإجابات حتى تحدد دوره.

## الخطوة 4: إنشاء الحسابات (الدخول بالمعرّف)
يدخل المستخدم بمعرّف قصير مثل `abdullah`، لا ببريد. Supabase يشترط بريدًا لكل حساب، فيُنشأ الحساب ببريد شكلي هو المعرّف متبوعًا بـ `@chem21.local`. يكمل الموقع هذا النطاق تلقائيًا عند الدخول، ولا تُرسل إليه أي رسائل.

1. افتح **Authentication**، ثم **Users**، ثم **Add user**، ثم **Create new user**.
2. في خانة Email اكتب المعرّف مع النطاق، مثل `abdullah@chem21.local`، ثم كلمة مرور قوية، وفعّل **Auto Confirm User**.
3. حدد الأدوار من **SQL Editor**:

```sql
update public.profiles set role = 'admin',    display_name = 'مالك المشروع' where email = 'owner@chem21.local';
update public.profiles set role = 'reviewer', display_name = 'عبدالله حمدي' where email = 'abdullah@chem21.local';
select email, display_name, role from public.profiles order by created_at;
```

ملاحظات:
- **المعرّف:** حروف إنجليزية صغيرة وأرقام فقط، بلا مسافات.
- **الدخول بالبريد الكامل:** ما زال ممكنًا لأي حساب أُنشئ ببريد حقيقي.
- **نسيان كلمة المرور:** لا يوجد بريد حقيقي تُرسل إليه رسالة الاستعادة. يحذف المشرف الحساب من **Authentication** ← **Users**، ثم ينشئه بنفس المعرّف وكلمة مرور جديدة، ثم يعيد تحديد دوره بأمر SQL أعلاه. سجل تعديلاته السابقة يبقى محفوظًا باسمه.

**الأدوار:**

| الدور | الصلاحية |
| --- | --- |
| `admin` | كل الصلاحيات |
| `reviewer` | التعديل والاعتماد والاستبعاد وسجل التعديلات وتصدير CSV |
| `viewer` | يرى الإجابات فقط |
| `pending` | لا يرى أي محتوى حتى يُفعَّل |

## الخطوة 5: الاستخدام
- افتح رابط الموقع على GitHub Pages، ثم «تسجيل الدخول» بالمعرّف وكلمة المرور.
- منشئ الاختبارات يعمل كما هو، ويقرأ البنك من قاعدة البيانات مباشرة.
- تصدير CSV يتم في المتصفح من صفحة بنك الأسئلة، للمراجع والمشرف فقط.

## التحديث لاحقًا

## حساب الطالب (التدريب فقط)
صُمم بناءً على توصيات الوكيل التربوي.

**ما يراه الطالب:** صفحتا «تدرّب» و«سجلي» فقط، دون أي إجابات جماعية ولا مراجعة ولا منشئ اختبارات. وقاعدة البيانات ترفض أي طلب منه لدوال المعلمين.

**تجربة الطالب:**
- **أول دخول:** يؤكد اسمه وشعبته، وهما معبّآن مسبقًا من المشرف، فيُثبَّتان ولا يعدّلهما إلا المشرف.
- **إعداد الجلسة:**
  - يختار الدروس وعدد الأسئلة (5 أو 10 أو 15 أو 20، والافتراضي 10).
  - يختار المستوى: متدرّج (الافتراضي)، أو أساسي، أو تطبيق، أو تفكير عليا.
  - يختار تفعيل المؤقت أو لا. المؤقت اختياري ومطفأ افتراضيًا، ولا يقفل الجلسة.
  - الأسئلة والبدائل تُخلط في كل جلسة.
- **التصحيح:** فوري بعد كل سؤال. يبدأ بسبب خطأ البديل الذي اختاره، ثم التفسير، ثم بقية البدائل عند الطلب.
- **بعد الجلسة:**
  - النتيجة حسب الدرس والمستوى.
  - زر «أعد الأخطاء»: يعرض سؤالًا آخر من الهدف نفسه لكل خطأ، ثم الأسئلة الأصلية في آخر الجلسة.
  - صفحة «سجلي»: نسبة التقدم في كل درس، وآخر الجلسات.
- **الحد اليومي:** 40 جلسة.

**صفحات الطاقم:**
- **«تقدم الطلاب»** للمعلم والمراجع والمشرف: الطلاب حسب الشعبة، وعدد الجلسات، ونسبة الإجابات الصحيحة، وآخر نشاط، والأهداف الأضعف.
- **«حسابات الطلاب»** للمشرف فقط:
  - **رفع ملف Excel:** الأعمدة الاسم والصف والشعبة، واختياريًا اسم المستخدم وكلمة المرور. تُعرض معاينة قبل الإنشاء، وفي الصفحة نموذج Excel جاهز للتحميل. يمكن أيضًا الكتابة سطرًا لكل طالب.
  - **بعد الإنشاء:** تحميل كلمات المرور في ملف Excel، أو طباعة بطاقات الدخول.
  - **القائمة:** تصفية بالصف والشعبة، وبحث بالاسم، وتصدير القائمة إلى Excel مع ملخص التدريب.
  - **تعديل الطالب:** الاسم، واسم المستخدم، والصف، والشعبة، والحالة (نشط أو موقوف).
  - **كلمة المرور:** يكتبها المشرف، أو تُولَّد تلقائيًا إن تركها فارغة.
  - **حذف الحساب:** نهائي، ويُحذف معه سجل تدريب الطالب.

3. **أنشئ الحسابات:** من الموقع: **حسابات الطلاب**، ثم الصق الأسماء، ثم **إنشاء الحسابات**. احفظ كلمات المرور أو اطبع البطاقات فورًا، لأنها لا تظهر مرة أخرى.
